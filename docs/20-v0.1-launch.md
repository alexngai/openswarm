## What v0.1 ships

### Single-agent CLI

- Anthropic via Claude Agent SDK (subscription, API key, or `CLAUDE_CODE_OAUTH_TOKEN`).
- OpenAI, xAI Grok, Google Generative AI (Gemini), DashScope (Qwen / Kimi) via Vercel AI SDK transports + the native engine path.
- `--model` accepts canonical ids or short aliases (`opus`, `sonnet`, `grok`, `kimi`, etc.); user overrides via `~/.openswarm/settings.json`.
- `--permission-mode` of `read-only`, `workspace-write`, `danger-full-access`.
- `--headless` emits structured JSONL for orchestrators / CI; honors stdin-driven approvals.
- `--resume <id|latest>` resumes prior sessions.
- `--no-plugins`, `--no-skills`, `--no-mcp`, `--no-hooks` opt-out flags.
- `doctor`, `init`, `help`, `version`, `login --provider <id>`, `logout --provider <id>` subcommands.

### Interactive REPL (OpenTUI/Solid on Bun)

- Markdown rendering with palette-tuned `SyntaxStyle.fromTheme(...)` and **language-aware syntax highlighting** for fenced code blocks (TypeScript, JavaScript, Markdown, Zig out of the box via Tree-sitter).
- Native table rendering inside markdown.
- Inline y/N approval prompts for elevation requests + bash-validation warnings (no `/approve` / `/deny` slash commands).
- Multi-line input (Shift+Enter / Ctrl+J newline; Enter submits). CRLF normalized on paste.
- Persistent prompt history at `~/.openswarm/history` (10k cap, dedup-consecutive, multi-line escape).
- Emacs keybindings: Ctrl+A/E/K/U/W (line motions + kill ring), Alt+B/F/D/Backspace (word motions), Ctrl+Y (yank), Up/Down + Ctrl+P/N (history navigation).
- Slash-command dropdown with arrow-key + Tab navigation.
- Compaction lifecycle UI + pending-permission status bar.

### Swarm orchestration

- `swarm run <tasks.jsonl>` — fanout across worker pool with concurrency cap, dead-letter, retry policies.
- Roles: `--role <name>` per-task or run-wide overlay; role-based addressing via `role:<name>` in `message.send`.
- Lane events streamed via JSONL — ~70 variants covering lifecycle, turns, tool use, tasks, permissions, coordination, retries, plugins, native engine, and (Phase 5) bash validation + worker lifecycle.
- Worker boot state machine: `spawning → ready_for_prompt → prompt_accepted → running → finished | failed`. Transitions emit `worker_lifecycle_changed` events.
- `TypedLaneEvent` discriminated union + `assertNeverEvent` exhaustiveness gate (incremental: 3 new variants typed, 70+ existing stay `unknown`).
- `WorkerPool`, `Orchestrator`, `WorkerHost`, `StandaloneHost`, ancestry tracking, message inbox with overflow handling, depth-limit enforcement.

### Tools (eight Tier 0 + tier 1/2/3 via plugins/skills/MCP)

| Tier | Source | Examples |
|---|---|---|
| Tier 0 | bundled | `bash`, `read_file`, `write_file`, `edit_file`, `multi_edit`, `glob`, `grep`, `todo_write` |
| Tier 1 | bundled (skills support) | `Skill` tool routes to `.claude/skills/` markdown skills |
| Tier 2 | MCP | Tools surfaced from MCP servers configured at `.mcp.json` or `~/.claude/mcp.json` |
| Plugins | `~/.openswarm/plugins/` (owned) + `~/.claude/plugins/` (read-only discovery) | User-installed plugin tools |

**Bash validation:** all `bash` invocations route through a 6-submodule pipeline (read-only / destructive / mode / sed / path / semantics) that blocks or warns based on the active permission mode and command intent. Block returns a structured `tool_result` error; Warn routes through the inline y/N prompt (TTY) or stdin approval (headless).

### Plugins, MCP, skills, hooks

- **Plugins:** `openswarm plugin install/enable/disable/list` slash + CLI subcommands. Two-file schema (`settings.json` for enable/disable, `installed.json` for manifest registry) at `~/.openswarm/plugins/`. Read-only discovery of `~/.claude/plugins/` for plugins installed via Claude Code.
- **MCP:** First-class stdio client + tool bridge. Per-server connect timeouts, fail-soft on individual server failures.
- **Skills:** `.claude/skills/` discovery + Skill tool dispatch.
- **Hooks:** PreToolUse / PostToolUse / SessionStart from `~/.claude/settings.json` and project `.claude/settings.json`. Wired through ToolDispatcher for uniform coverage across tiers.

### Auth

openswarm owns zero auth code per Anthropic's Terms of Service. Three Anthropic paths (API key, subscription via `claude auth login`, long-lived `CLAUDE_CODE_OAUTH_TOKEN`). Other providers use plain env-var API keys (`OPENAI_API_KEY`, `XAI_API_KEY`, `GOOGLE_GENERATIVE_AI_API_KEY`, `DASHSCOPE_API_KEY`).

## Known limitations at v0.1

These ship as documented limitations, not surprises:

| Area | Limitation | Workaround | Resolution path |
|---|---|---|---|
| OpenAI ChatGPT Plus / Pro auth (P4) | No OAuth flow yet | Use `OPENAI_API_KEY` for direct API access | Phase 6 (blocked) |
| Per-server MCP failure classification (TO2) | Failures not classified per server | Per-server config + `--no-mcp` to disable globally | v0.2 candidate |
| Server-side token preflight (A8) | Compaction triggers are local heuristics, not API-reported counts | Manual `/compact` if you hit a context limit | v0.2 candidate |
| Branch-lock / stale-base (A2) | Partial git coordination from M3a; full claw-parity audit pending | Use single-branch swarm runs | v0.2 audit + decide |
| Anthropic API-key path without Agent SDK (P5) | Subscription path is the primary tested route | API-key path works but lightly exercised | v0.2 hardening |
| Spinner polish (T8) | Functional but less polished than claw's ✔/✘ transitions | Cosmetic only | Defer indefinitely |
| Cron scheduler (PS3) | `CronRegistry` is in-memory; scheduled tasks never fire | Don't rely on cron in v0.1 | Defer until needed |
| Recovery recipes (A3), policy engine (A4), sandbox (A6), green contract (A7) | Not present | Inline retry / explicit error handling | Defer; usage-driven |
| Extended slash commands (PS4–PS6: `/ultraplan`, `/teleport`, deeper `/plan`) | Not present | Could ship as plugins | Plugin candidates |
| Tier-3 tools (TO3 `pdf_extract`, TO4 `repl`, TO5 `powerShell`) | Not present | Use `bash` + write-to-file | Defer; low value |
| Mock parity harness (D1) | Not present | Live `scripts/smoke-m4b.sh` covers provider paths | Build when a regression bites |

## What v0.1 explicitly does NOT promise

- **API stability across major versions.** Pre-1.0; expect breaking changes.
- **Cron / scheduler reliability.** `CronRegistry` is a stub.
- **Windows support.** macOS-first; Linux likely works but untested.
- **Trust-callback support in worker lifecycle.** `trust_required` is a reserved state — Claude Agent SDK doesn't surface a trust prompt today.
- **Schema versioning on lane events.** Additive-by-convention (per [doc 17 Q7](17-parity-design-questions.md)). New variants are added freely; consumers ignore unknowns.
- **Per-language Tree-sitter palette colors.** Fenced blocks get language-aware *tokenization*; per-token color theming uses OpenTUI's defaults until a real palette ships.
