## Stage 7B — Cascade adapter + spawn / commit / cleanup · ~3d

**Goal:** introduce `src/swarm/adapters/cascade-adapter.ts`, wire it into spawn (cwd handoff), commit (post-task commit driver), and cleanup (worker FSM `drained`/`finished`/`failed` transitions → deallocate). After 7B, a `Fanout` team of three with `branchPolicy: { kind: "stream" }` produces three streams, three worktrees, three independent commits, three deallocated worktrees at team end.

### New file: `src/swarm/adapters/cascade-adapter.ts`

```typescript
import { MultiAgentRepoTracker, type AgentWorktree, type Stream }
  from "git-cascade";
import type { TaskPacket } from "../host.js";
import type { BranchPolicy } from "../policies.js";

export interface CascadeAdapterOptions {
  /** Repo root. Defaults to process.cwd(). */
  readonly repoPath?: string;
  /** Forwarded as `eventPrefix` to tracker. Defaults to "x-cascade". */
  readonly eventPrefix?: string;
  /** Called for every git-cascade event so the topology can lift it to a LaneEvent. */
  readonly onEvent: (method: string, params: Record<string, unknown>) => void;
}

export interface Allocation {
  readonly streamId: string;
  readonly branchName: string;
  readonly worktreePath: string;
}

export class CascadeAdapter {
  private tracker: MultiAgentRepoTracker | undefined;
  private readonly opts: CascadeAdapterOptions;

  constructor(opts: CascadeAdapterOptions) { this.opts = opts; }

  /** Lazy-open. First call creates `.git-cascade/tracker.db`. */
  private getTracker(): MultiAgentRepoTracker {
    if (this.tracker === undefined) {
      this.tracker = new MultiAgentRepoTracker({
        repoPath: this.opts.repoPath ?? process.cwd(),
        eventPrefix: this.opts.eventPrefix ?? "x-cascade",
        emit: this.opts.onEvent,
      });
    }
    return this.tracker;
  }

  /**
   * Resolve a `stream`/`fork` policy into a fresh worktree.
   * Throws on unsupported policy.kind (caller should pre-filter).
   */
  allocateForTask(
    task: TaskPacket,
    agentId: string,
    displayName: string,
  ): Allocation {
    const policy = task.branchPolicy as BranchPolicy;
    const tracker = this.getTracker();
    let streamId: string;
    if (policy.kind === "stream") {
      streamId = tracker.createStream({
        name: policy.name ?? displayName,
        agentId,
        baseCommit: policy.baseStreamId,  // when undefined, tracker uses HEAD
      });
    } else if (policy.kind === "fork") {
      streamId = tracker.forkStream({
        parentStreamId: policy.parentStreamId,
        name: policy.name ?? displayName,
        agentId,
      });
    } else {
      throw new Error(`CascadeAdapter.allocateForTask: unsupported policy.kind=${policy.kind}`);
    }

    const worktreePath = `.git-cascade/worktrees/${agentId}`;  // V0.7.Q3
    const wt = tracker.createWorktree({
      agentId,
      path: worktreePath,
      branch: `stream/${streamId}`,
    });
    return { streamId, branchName: `stream/${streamId}`, worktreePath: wt.path };
  }

  /** Drive `commitPolicy: auto` for `stream`/`fork` tasks. */
  commitForTask(
    streamId: string,
    agentId: string,
    worktreePath: string,
    message: string,
  ): { commit: string; changeId: string } {
    return this.getTracker().commitChanges({
      streamId, agentId, worktree: worktreePath, message,
    });
  }

  /** Idempotent. Safe to call for agents that never allocated. */
  deallocateForAgent(agentId: string): void {
    if (this.tracker === undefined) return;
    try {
      this.tracker.deallocateWorktree(agentId);
    } catch { /* deallocate is idempotent in semantics; swallow */ }
  }

  /** For pipeline cascade trigger (7C). */
  cascadeRebase(fromStreamId: string):
      { updated: string[]; failed: string[]; deferred: string[] } {
    const result = this.getTracker().cascadeRebase({
      sourceStreamId: fromStreamId,
      strategy: "stop_on_conflict",
    });
    return {
      updated: result.updated.map(s => s.streamId),
      failed: result.failed.map(s => s.streamId),
      deferred: result.deferred.map(s => s.streamId),
    };
  }

  /** For orphan reaper (7D). */
  listWorktrees(): AgentWorktree[] {
    return this.tracker?.listWorktrees() ?? [];
  }

  /** For CLI `git-cascade list` (7E). */
  listStreams(): Stream[] {
    return this.tracker?.listStreams() ?? [];
  }

  /** Idempotent. Safe in shutdown path. */
  close(): void {
    this.tracker?.close();
    this.tracker = undefined;
  }
}
```

### Commit driver — the previously-missing piece

**Audit finding:** today's [fanout.ts:752 `emitCommitPolicyNoop`](../src/swarm/topologies/fanout.ts) shows `commitPolicy` is **purely advisory** — emits an event, no actual commit. v0.7 7B introduces the real commit step. Locked here as V0.7.Q13:

> **V0.7.Q13 (new) — commit driver placement.** The post-task commit step runs in the topology, immediately after `handle.wait()` returns `status === "success"`, before the worker FSM transitions to `drained`/`finished`. It runs only when `commitPolicy.kind === "auto"` AND `branchPolicy.kind ∈ {"stream", "fork"}` AND allocation exists. For all other combinations, behavior is unchanged (no commit driver — agent's own git commits via bash tool stand). The commit message is `commitPolicy.message ?? "swarm-harness: <role> task <taskId>"`.

```typescript
// Inserted in topology after `await handle.wait()` succeeds, before deallocate.
if (
  allocation !== undefined &&
  task.commitPolicy.kind === "auto" &&
  ctx.cascadeAdapter !== undefined
) {
  const message = task.commitPolicy.message ?? `swarm-harness: ${task.role ?? "agent"} task ${task.id}`;
  const { commit, changeId } = ctx.cascadeAdapter.commitForTask(
    allocation.streamId, handle.agentId, allocation.worktreePath, message,
  );
  ctx.host.emit({
    type: "cascade_stream_committed",
    payload: { taskId: task.id, streamId: allocation.streamId, commit, changeId },
  });
}
```

### Default-policy resolver

New helper in `src/swarm/policies.ts` or alongside `TeamSession`:

```typescript
export function defaultBranchPolicyForTopology(
  topology: TopologyKind,
  memberRole: string,
  context: { stageIndex?: number; prevStreamId?: string; baseStreamId?: string },
): BranchPolicy {
  switch (topology) {
    case "fanout":      return { kind: "stream" };
    case "committee":   return { kind: "stream" };
    case "pipeline":
      return context.stageIndex === 0
        ? { kind: "stream" }
        : { kind: "fork", parentStreamId: context.prevStreamId! };
    case "coordinator":
      return memberRole === "root"
        ? { kind: "stream" }
        : { kind: "fork", parentStreamId: context.baseStreamId! };
    case "peer-team":   return { kind: "fork", parentStreamId: context.baseStreamId! };
    case "critic-loop": return memberRole === "critic" ? { kind: "none" } : { kind: "stream" };
  }
}
```

Topology-level wiring resolves `context.prevStreamId` / `context.baseStreamId` at member-spec time — pipeline carries it from prior stage (7C); coordinator/peer-team allocate a "team base stream" at team start (extension to TeamSession in 7D).

## Open implementation questions (post-audit)

Two new questions surfaced during the docs/30 audit. Both **locked here** since they affect 7B.

### V0.7.Q13 — Commit driver placement (surfaced 2026-05-26)

**Audit finding:** today's [fanout.ts:752 `emitCommitPolicyNoop`](../src/swarm/topologies/fanout.ts) shows `commitPolicy` is purely advisory — emits an event, no actual commit. Docs/29 said "host.commitTask" wires `tracker.commitChanges` but no such function exists.

**Decision:** the v0.7 commit driver runs in the **topology**, immediately after `handle.wait()` returns success, before deallocate. Only fires when `commitPolicy.kind === "auto"` AND `branchPolicy.kind ∈ {"stream", "fork"}`. For all other combinations, the agent's bash-tool git commits stand (today's behavior).

Rationale: putting the commit step at the host layer would require intercepting agent bash calls — a much wider surface change. The topology has the task + worker handle + allocation in scope; one clean call site per topology.

### V0.7.Q14 — SpawnRequest.cwd field (surfaced 2026-05-26)

**Audit finding:** [SpawnRequest](../src/swarm/host.ts) (host.ts:160) has 14 fields today; **`cwd` is not one of them.** Subprocess always uses `process.cwd()`.

**Decision:** add `readonly cwd?: string` to `SpawnRequest`. `StandaloneHost` (which actually launches subprocesses) plumbs it to the child process spawn options. When undefined: behavior unchanged. The topology populates `cwd` from the cascade adapter's allocation result.

Locked in §Cross-stage primitive B above. Wired in 7B.
