# v0.5 — Team daemon implementation plan

Companion to [docs/25-team-orchestration.md](25-team-orchestration.md) (architecture) and [docs/27-v0.4-teams-implementation-plan.md](27-v0.4-teams-implementation-plan.md) (v0.4 plan; daemon was deferred there). This doc is the master execution plan for the v0.5 team daemon — the piece that flips `team send` / `list` / `stop` / `kill` from CLI stubs to working cross-process commands.

**Authoring date:** 2026-05-03.
**Status:** design lock.
**Supersedes:** [docs/27 §13](27-v0.4-teams-implementation-plan.md#stage-breakdown) deferral notes for the long-lived team daemon. [docs/25 §17.2](25-team-orchestration.md#172-constrained--works-with-caveats) "team send/list/stop/kill are CLI stubs" limitation.
**Anchor:** [docs/00-vision.md](00-vision.md) — teams as services rather than batch jobs.

---

## TL;DR

Ship the long-lived team daemon. Per-team forked process per `team start --detach`. CLI commands `team send`, `team list`, `team stop`, `team kill`, `team logs` talk to a Unix socket per team under `${XDG_RUNTIME_DIR}/swarm-harness/teams/<name>/`. No crash recovery in v0.5 — `events.jsonl` is the forensic trail. Multi-engine peer parity, long-lived workers (4D), and the four shipped topologies are inherited unchanged from v0.4.

**Scope:** stages 5E.1–5E.7 below. **Estimate:** ~7.5 days. **Acceptance:** §6.

---

## Why now

[docs/25 §17.2](25-team-orchestration.md#172-constrained--works-with-caveats) documents the limitation: in v0.4, `team start` is synchronous and exits when the team finishes; `team send`/`list`/`stop`/`kill` are CLI stubs that print "deferred to v0.5+" and exit 2 ([src/cli/team.ts:321-351](../src/cli/team.ts)).

The daemon turns teams into services: `team start gsd --detach` returns immediately, the team keeps running, and a second shell can `team send gsd "review HEAD"` to push new prompts. Long-lived workers (shipped in 4D, [src/swarm/worker-lifecycle.ts](../src/swarm/worker-lifecycle.ts)) finally get exercised across shells.

## Design lock — V0.5 (daemon)

Question numbers are v0.5-daemon-local. Carries forward decisions from [docs/25 §2](25-team-orchestration.md#2-decision-summary) and [docs/27 D4–D7](27-v0.4-teams-implementation-plan.md#design-lock--v04). Eight new locks below; all resolved before stage 5E.1.

### V0.5.Q1 — Daemon scope (per-team vs host)

**Decision:** per-team forked daemon. One OS process per running team. Each daemon hosts exactly one `TeamSession`.

Rejected alternatives:
- Single host daemon (multi-team-in-one-process) — would require multi-team `Orchestrator` first; bigger blast radius; closes [§docs/25 §6.4](25-team-orchestration.md#64-multi-team-in-one-orchestrator) prematurely.
- Hybrid (per-team daemon + shared `registry.jsonl`) — same architecture as per-team; the registry file is a cheap addition deferrable to v0.6 if `team list` directory walks feel slow.

Reversibility: per-team → host daemon is additive (the host can spawn per-team daemons). The reverse is harder. Locking per-team preserves both options.

### V0.5.Q2 — Default attachment behavior

**Decision:** `team start <template>` stays attached by default — preserves v0.4 byte-identical behavior. `--detach` is the new opt-in flag that double-forks the daemon and returns 0 once the socket is bound.

### V0.5.Q3 — Socket location

**Decision:** `${XDG_RUNTIME_DIR}/swarm-harness/teams/<name>/`. Files in that directory: `daemon.sock`, `daemon.pid`, `events.jsonl`, `team-state.json`.

On darwin where `XDG_RUNTIME_DIR` is unset, fall back to `${TMPDIR}/swarm-harness/teams/<name>/`. Project-local `.swarm-harness/` rejected — most use cases are user-global; project-scoped daemons can be added later via a `--scope project` flag if needed.

### V0.5.Q4 — Output streaming model

**Decision:** daemon writes `events.jsonl` (append-only, line-per-event). New `team logs <name>` subcommand reads it; `team logs <name> --follow` tails it via `fs.watch` + offset tracking. Mirrors `docker logs`. Avoids long-held streaming sockets.

Each line is one `LaneEvent` JSON-serialized + a top-level `ts` (ms epoch). Schema is the existing `LaneEvent` union from [src/swarm/events.ts](../src/swarm/events.ts) — no new types.

### V0.5.Q5 — Crash recovery

**Decision:** none in v0.5. Daemon crash = team dead. Re-launching is the upgrade and recovery path.

Reasoning: re-attaching to live worker subprocesses requires worker-side protocol changes (workers exit on stdin EOF today), daemon checkpointing of correlation tables + FSM state, and a re-handshake protocol — meaningfully larger than "ship a daemon." The only realistic value is bug-restart recovery, and `team start` again is bounded cost for typical minutes-hours team durations.

Sub-decisions:

| # | Question | Decision |
|---|---|---|
| **Q5a** | Worker death when daemon dies | Workers exit cleanly via stdin-close (today's behavior). No orphan reaper needed. Tested via `kill -9` of the daemon. |
| **Q5b** | Stale socket file cleanup | At `team start`, if `daemon.sock` exists but `kill -0 <pid>` fails, unlink the socket + pid file and proceed. |
| **Q5c** | `team list` for crashed teams | Filter out by default. `team list --all` (5E.4 stretch) shows crashed/completed entries. |
| **Q5d** | `events.jsonl` rotation | Punt to v0.6+. Document "rotate manually if it grows" for v0.5. |

Forward path if recovery becomes painful: v0.6+ adds `team-state.jsonl` checkpointing such that `team start --resume <name>` re-creates the team shape (members, roles, scope) with fresh worker subprocesses. Worker re-attach is a further v0.7+ option. Both are additive — locking "no recovery" in v0.5 doesn't paint into a corner.

### V0.5.Q6 — `team send` semantics

**Decision:** fire-and-forget. RPC returns when the message is enqueued in the team's inbox. Caller polls via `team logs --follow` for output.

At-least-once delivery: daemon flushes the inbox enqueue before sending the RPC reply. SIGTERM during enqueue may drop one in-flight message — documented.

### V0.5.Q7 — Concurrent `team start` with same name

**Decision:** reject with `error: team "<name>" already running (pid X). Run 'team stop <name>' first.` Existing socket file + live pid is the lock. Stale-socket case (V0.5.Q5b) recovers transparently.

### V0.5.Q8 — Upgrade path

**Decision:** out of scope for v0.5. `team stop <name>` then `team start <name>` is the upgrade story. Document it.

Reasoning: hot-upgrade (binary swap with running workers) requires the same machinery as crash recovery — out of scope per Q5.

## Stage breakdown

7 stages, sequenced for protocol-then-daemon-then-CLI ordering. Each stage ends in a shippable, tested state. Stage commits follow the `v0.5 stage 5E.x: <summary>` pattern (mirrors v0.2/v0.3/v0.4).

Stage prefix is `5E` to avoid collision with `5D` (swarm watch TUI) and `5A`–`5C` already named in [docs/25 §13](25-team-orchestration.md#13-phased-delivery).

### Stage 5E.1 — Daemon protocol definition · ~0.5d

**Code:**
- New: `src/swarm/team-daemon-protocol.ts` — JSON-RPC frame shapes mirroring `src/swarm/ipc/protocol.ts`. Methods: `status`, `send_prompt`, `stop`, `kill`. Notifications: `team_event` (subscribe is deferred — v0.5 callers tail `events.jsonl` instead).
- New: zod schemas for each request / response.

**Tests:**
- New: `src/swarm/team-daemon-protocol.test.ts` (~80 LOC) — round-trip serialization + invalid-input rejection.

**Acceptance:** schema accepts well-formed RPCs; rejects malformed with clear errors.

### Stage 5E.2 — Daemon entry + double-fork · ~2d

**Code:**
- New: `src/swarm/team-daemon.ts` — daemon process entry. Construction: takes a `TeamSpec` + paths object (`{sockPath, pidPath, eventsPath, statePath}`); binds Unix socket; instantiates `Orchestrator` + `runTeam(spec)`; subscribes to lane events and appends each as a JSONL line. Signal handlers: SIGTERM/SIGINT → graceful drain (uses 4D `drain` IPC frame); SIGKILL handled by OS (workers exit on stdin EOF per V0.5.Q5a).
- New: `src/cli/team-daemon-entry.ts` — exec entry called by the parent forker. Reads spec from a temp file path passed in argv; calls into `team-daemon.ts`.

**Tests:**
- New: `src/swarm/team-daemon.test.ts` — fork lifecycle, socket cleanup on exit, signal handling. Uses a minimal in-process spec to avoid spawning real workers in the unit suite.

**Acceptance:** team-daemon process can be forked from a test harness, accepts a connection on its socket, exits cleanly on SIGTERM with `daemon.sock` and `daemon.pid` removed.

### Stage 5E.3 — `team start --detach` wiring · ~0.5d

**Code:**
- Modify: `src/cli/team.ts:runTeamStart` — new `--detach` branch. Serializes the resolved `TeamSpec` to a temp file; double-forks `team-daemon-entry.ts` with the temp file path in argv (via `child_process.spawn` with `detached: true, stdio: ['ignore', logFd, logFd]`). Parent retries `connect(socket)` for up to 2s (8 × 250ms) to confirm bind, then returns 0.
- Modify: `src/cli/argv.ts` — add `--detach` flag to `team start`.

**Tests:**
- Modify: `src/cli/team.test.ts` — assert `--detach` forks (use a stubbed forker); non-detach behavior byte-identical to v0.4 (regression test).

**Acceptance:** `swarm-harness team start gsd --detach` returns within 2s; daemon visible in `team list` (depends on 5E.4); existing non-detach path unchanged.

### Stage 5E.4 — `team send` / `list` / `stop` / `kill` RPC · ~1.5d

**Code:**
- Modify: `src/cli/team.ts` — replace `runTeamSend`/`List`/`Stop`/`Kill` stubs with real socket talk.
  - `team list` walks `${XDG_RUNTIME_DIR}/swarm-harness/teams/`, runs `kill -0 <pid>` per entry, returns live ones (V0.5.Q5c).
  - `team send` connects to socket; sends `send_prompt` RPC; returns ack.
  - `team stop` sends `stop` RPC (graceful drain via 4D `drain`); waits for daemon exit.
  - `team kill` sends `kill` RPC then SIGKILL after 5s timeout.
- Daemon-side handlers in `team-daemon.ts` for each RPC.
- Stale socket cleanup at `team start` (V0.5.Q5b).
- Duplicate-name rejection (V0.5.Q7).

**Tests:**
- New: `src/cli/team-rpc.test.ts` — start a real (forked) daemon in a test harness; verify each command via socket. Includes stale-socket-cleanup case + duplicate-name-rejection case.

**Acceptance:** end-to-end RPC against a running daemon for all four commands. Stale socket recovered. Duplicate `team start` rejected with clear error.

### Stage 5E.5 — `events.jsonl` + `team logs --follow` · ~1d

**Code:**
- Modify: `src/swarm/team-daemon.ts` — wire `host.events()` subscription to the JSONL writer. Append-only, flush per event. Each line: `{ts, ...laneEvent}`.
- New: `src/cli/team-logs.ts` — read `events.jsonl`; if `--follow`, `fs.watch` + offset-tracked tail. Handles file rotation (none in v0.5, but logic should not crash on truncation).
- Modify: `src/cli/main.ts` + `src/cli/argv.ts` — wire `team logs <name> [--follow]` subcommand.

**Tests:**
- New: `src/cli/team-logs.test.ts` — write a fixture jsonl, exercise tail + `--follow` (with a fake clock + `fs.watch` shim).
- New: integration in `src/cli/team-rpc.test.ts` — spawn daemon, run a small team, assert `events.jsonl` shape matches `LaneEvent` serialization.

**Acceptance:** `team logs gsd` shows up to last event; `team logs gsd --follow` streams live events as the team progresses.

### Stage 5E.6 — Tests + smoke · ~1.5d

**Code:**
- New: `scripts/smoke-team-daemon.sh` — starts daemon detached, sends 2 prompts, lists, stops. End-to-end smoke against a small fixture team.
- Add unit coverage where stages 5E.2–5E.5 left gaps: daemon crash mid-RPC; socket conflict on duplicate `team start`; SIGTERM during in-flight RPC; `team kill` timing.

**Tests:**
- ~30–40 new test cases land here. Estimated baseline: 1704 (v0.4 close-out) + ~40 = 1744.

**Acceptance:** `tsc --noEmit` clean; `npm test` ≥1740 / 0 fail; `scripts/smoke-team-daemon.sh` green.

### Stage 5E.7 — Docs · ~0.5d

**Code:**
- Update: [docs/25 §17.2](25-team-orchestration.md#172-constrained--works-with-caveats) — flip "team send/list/stop/kill are CLI stubs" → "shipped via team daemon, see [docs/28](28-v0.5-daemon-plan.md)".
- Update: [docs/25 §17.3](25-team-orchestration.md#173-future-work-not-in-v04) — remove "long-lived team daemon" from v0.5 deferred list.
- Update: [docs/25 §13](25-team-orchestration.md#13-phased-delivery) — add 5E row to v0.5 table.

**Acceptance:** docs reflect shipped state. Tag `v0.5-daemon` (or roll into `v0.5` if shipping with 5A–5D).

## Acceptance criteria (release gate)

All of the following must hold before tagging the daemon work as shipped:

1. **Backward compat preserved.** `swarm-harness team start gsd` (no `--detach`) byte-identical behavior to v0.4. Existing single-agent CLI paths unchanged. `swarm run tasks.jsonl` byte-identical results.jsonl as v0.4.

2. **Detach mode works.** `swarm-harness team start gsd --detach` returns within 2s; daemon visible in `team list`.

3. **Send delivers.** `team send gsd "prompt"` enqueues to the team entry point per V0.4.Q4 default (root for coordinator topologies; broadcast for peer-team).

4. **Stop drains gracefully.** `team stop gsd` uses the 4D `drain` IPC frame; daemon exits within ~30s of last in-flight task completing.

5. **Kill terminates fast.** `team kill gsd` terminates daemon + workers within 5s.

6. **List filters live.** `team list` shows live daemons only; stale (crashed) entries filtered (V0.5.Q5c).

7. **Logs read + follow.** `team logs gsd` reads up to last event; `--follow` streams live.

8. **Stale-socket recovery.** `team start gsd --detach` succeeds even if a previous daemon left a stale socket file (V0.5.Q5b).

9. **Duplicate rejection.** `team start gsd --detach` with a live `gsd` daemon errors with the V0.5.Q7 message.

10. **Worker cleanup on daemon SIGKILL.** `kill -9 <daemon-pid>` → worker subprocesses exit within 5s (V0.5.Q5a).

11. **Test posture.**

| Suite | Baseline (v0.4 close-out) | v0.5-daemon target |
|---|---|---|
| `tsc --noEmit` | clean | clean |
| `npm test` | 1704 / 0 fail | ≥1740 / 0 fail |
| Live smoke | 7 categories | 8 categories (+ team-daemon) |

## Risks & mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Double-fork detach is platform-finicky | Med | Med | Use Node `child_process.spawn({detached: true})` + `unref()` pattern; CI tests on darwin + linux. |
| Worker subprocess orphans on daemon SIGKILL | Med | High | Workers exit on stdin EOF (today's behavior — V0.5.Q5a); explicit `kill -9` test in 5E.6. |
| Stale socket files block subsequent `team start` | High | Low | V0.5.Q5b cleanup; integration test in 5E.4. |
| `events.jsonl` unbounded growth in long teams | Low | Low | Document; manual rotation for v0.5; v0.6 considers built-in rotation. |
| Race: `team send` arrives before daemon socket binds | Med | Low | Bind-ack via 250ms × 8 = 2s retry loop in parent forker (5E.3). |
| CLI breaking change to existing `team start` (no `--detach`) | Low | High | 5E.3 keeps non-detach path byte-identical; regression test. |
| `XDG_RUNTIME_DIR` unset on darwin breaks defaults | Med | Med | `TMPDIR` fallback; documented; tested on darwin. |
| Daemon SIGTERM during `send_prompt` loses message | Low | Low | Daemon flushes pending writes before exit; document at-least-once semantics in V0.5.Q6. |
| 7.5d estimate slips | Med | Med | 5E.3, 5E.4, 5E.5 are independent after 5E.2 ships; can ship 5E.4 first as `team-daemon-rc` and add 5E.5 later. |
