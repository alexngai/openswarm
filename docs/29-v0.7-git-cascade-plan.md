# v0.7 — git-cascade adapter implementation plan

Companion to [docs/25-team-orchestration.md §10.4](25-team-orchestration.md#104-git-cascade--branchpolicy-adapter-v07-q7) (architecture). This doc is the master execution plan for the v0.7 git-cascade integration — the piece that flips swarm-harness from "all members share one cwd, stomping each other's edits" to "each member runs in its own git worktree backed by a stream-based workflow."

**Authoring date:** 2026-05-04.
**Status:** design lock.
**Supersedes:** [docs/25 §10.4](25-team-orchestration.md#104-git-cascade--branchpolicy-adapter-v07-q7) for the v0.7 MVP scope (7A); §10.4's full vision (commit / merge / cascade) is staged for 7B + 7C.
**Anchor:** [docs/00-vision.md](00-vision.md), [docs/05-swarm-model.md](05-swarm-model.md), [docs/25 §2 Q7](25-team-orchestration.md#2-decision-summary).

## TL;DR

Ship the worktree-per-member primitive. Each member spec'd with `branchPolicy: { kind: "stream" | "fork", ... }` gets a dedicated git worktree under `.swarm-harness/worktrees/<streamId>/` and the spawned worker's `cwd` is set to that worktree. Inside the worktree, `bash` / `write_file` / `edit_file` operate in isolation — parallel members can't stomp each other's edits.

**Out of scope for 7A:** commit-integration (Change-Id trailers, audit log) → 7B. Merge + cascade rebase → 7C. Per-topology default branch policies → 7D.

**Scope:** stages 7A.1–7A.5 below. **Estimate:** ~1d. **Acceptance:** §6.

---

## Why now

[docs/25 §10.4](25-team-orchestration.md#104-git-cascade--branchpolicy-adapter-v07-q7) documents the concurrency hazard: parallel topologies (Fanout, PeerTeam, Committee) run multiple members against the same `cwd`. There's no filesystem isolation; if two members both `edit_file` the same path, the last writer wins. That's a real correctness gap when teams of agents touch overlapping files.

git-cascade is your own npm package (`git-cascade@0.0.7`) explicitly built for this — `MultiAgentRepoTracker` provides per-agent worktrees + stream-based branching + audit log. Wiring it as a `BranchPolicy` adapter gives swarm-harness the headline "agents-on-isolated-worktrees" experience without re-implementing any of the underlying git management.

## Design lock — V0.7 (git-cascade MVP)

Question numbers are v0.7-local. Carries forward decisions from [docs/25 §2 Q7](25-team-orchestration.md#2-decision-summary). Eight new locks below; all resolved before stage 7A.1.

### V0.7.Q1 — Worktree path scheme

**Decision:** project-local under `${repoPath}/.swarm-harness/worktrees/<streamId>/`. `repoPath` is `process.cwd()` at orchestrator start (the assumed git repo root); `streamId` is the git-cascade-assigned id. Add `.swarm-harness/worktrees/` to `.gitignore` if not already (operators usually have `.swarm-harness/` ignored already).

Rejected: `${XDG_STATE_HOME}/swarm-harness/worktrees/...` (user-global) — git-cascade's `createWorktree` is repo-relative; cross-repo paths complicate cleanup + git's worktree registry.

### V0.7.Q2 — cwd plumbing on spawn

**Decision:** `SpawnRequest` gains optional `cwd?: string`. `StandaloneHost.spawn` resolves the policy → worktree path → sets `cwd` on the `SpawnWorkerArgs`. Spawner already supports cwd (line 130); no spawner change.

For test fakes: existing tests don't pass cwd; default `process.cwd()` continues to work. Net zero for existing tests.

### V0.7.Q3 — `BranchPolicy` extension

**Decision:** add two variants to the existing union (no breaking changes):

```ts
export type BranchPolicy =
  | { readonly kind: "none" }
  | { readonly kind: "reuse"; readonly branch: string }
  | { readonly kind: "create"; readonly from: string; readonly name?: string }
  // NEW v0.7:
  | { readonly kind: "stream"; readonly baseStreamId?: string; readonly name?: string }
  | { readonly kind: "fork"; readonly parentStreamId: string; readonly name?: string };
```

Each new variant carries a `name?` field forwarded to git-cascade's `createStream({ name })` for human-readable identifiers. The existing 3 variants remain no-ops at the spawn level (their semantics are member-side concerns, not orchestrator concerns) — only `stream` and `fork` trigger worktree creation in 7A.

### V0.7.Q4 — Cleanup semantics

**Decision:** leave worktrees in place after worker exit. Do not call `tracker.removeWorktree`. Operators can clean up manually via `git worktree remove` or a future `swarm-harness team prune-worktrees` CLI.

Rationale: git-cascade is built around audit trails and rollback. Tearing down a worktree means losing the per-agent work history. For 7A's MVP "let me see what each agent did" is more valuable than disk-space recovery. 7D may add cleanup-on-exit as an opt-in flag.

### V0.7.Q5 — BranchLock interaction

**Decision:** members with `kind: "stream" | "fork"` bypass the existing `BranchLock` mechanism. Each stream creates a unique branch (`stream/<id>`) so there's no contention to lock. The existing M3b BranchLock continues to apply for `kind: "create"` and `kind: "reuse"` (which share branches across agents).

This is a no-op behavior change: BranchLock today only fires when two members try to acquire the same branch name, which can't happen with stream-unique names.

### V0.7.Q6 — Tracker lifecycle

**Decision:** one `MultiAgentRepoTracker` instance per `Orchestrator`. Constructed lazily on first `kind: "stream"|"fork"` spawn (or eagerly if `--git-cascade` is passed). Closed on orchestrator dispose.

Storage: git-cascade's tracker uses a sqlite-backed db at `${repoPath}/.swarm-harness/git-cascade/tracker.db`. Survives orchestrator restarts so cascade rebases can find prior streams.

### V0.7.Q7 — Adapter shape (mirrors 5B + 6A patterns)

**Decision:** new module `src/swarm/adapters/git-cascade-branch-policy.ts` exporting:

```ts
export interface BranchPolicyAdapter {
  resolve(policy: BranchPolicy, agentId: AgentId): Promise<BranchPolicyResolution>;
  dispose(): Promise<void>;
}
export interface BranchPolicyResolution {
  /** When set, spawn the worker with this cwd. */
  readonly cwd?: string;
  /** Stream id (for downstream commit/merge integration in 7B+). */
  readonly streamId?: string;
  /** Branch name git-cascade assigned. */
  readonly branch?: string;
}
export class GitCascadeBranchPolicyAdapter implements BranchPolicyAdapter { ... }
```

`StandaloneHostOptions` gains `branchPolicyAdapter?: BranchPolicyAdapter` (default: identity adapter that returns `{}` so existing `kind: "none"|"reuse"|"create"` callers see no behavior change).

### V0.7.Q8 — CLI flag

**Decision:** `--git-cascade` for `swarm run`. Composable with `--opentasks` and `--agent-inbox` (all three wrap the same StandaloneHost). When set, swarm-harness constructs a `GitCascadeBranchPolicyAdapter` and passes it to StandaloneHost.

Future: `swarm-harness topology` and `team start` also gain the flag in 7B+ once defaults-per-topology lands and the flag is genuinely useful for non-`swarm run` paths.

### Stage 7A.3 — `GitCascadeBranchPolicyAdapter` · ~3h

**Code:**
- Add dep: `git-cascade@^0.0.7`.
- Modify: `src/swarm/adapters/git-cascade-branch-policy.ts` — implement `GitCascadeBranchPolicyAdapter`:
  - Constructor takes `{ repoPath, dbPath?, eventEmitter? }`. Lazy-creates `MultiAgentRepoTracker`.
  - `resolve(policy, agentId)`:
    - For `kind: "stream"`: `tracker.createStream({ name, agentId, baseStreamId? })` → `tracker.createWorktree({ agentId, path, branch })` → return `{ cwd, streamId, branch }`.
    - For `kind: "fork"`: `tracker.forkStream({ parentStreamId, name, agentId })` → same worktree creation → same return shape.
    - For other kinds: return `{}` (no-op; caller uses default cwd).
  - `dispose()`: close tracker db.
- Modify: `src/swarm/standalone-host.ts`:
  - Constructor takes `branchPolicyAdapter?: BranchPolicyAdapter`. Default identity.
  - `spawn` calls `await this.branchPolicyAdapter.resolve(...)` before building SpawnWorkerArgs; sets `cwd` from the resolution.
  - `dispose` calls `await this.branchPolicyAdapter.dispose()`.

**Tests:**
- New: `src/swarm/adapters/git-cascade-branch-policy.test.ts` — uses git-cascade with a tmpdir repo. Three cases:
  - `kind: "stream"` creates a fresh stream + worktree, returns cwd.
  - `kind: "fork"` creates a child stream with parent linkage.
  - Other policy kinds return `{}` (identity behavior).

**Acceptance:** adapter creates real worktrees against a real git repo in tests; teardown leaves worktrees in place (per Q4); tracker.db persists across reopens.

## Acceptance criteria (release gate)

All must hold before tagging `v0.7-7A`:

1. **Backward compat preserved.** `swarm run tasks.jsonl` (no `--git-cascade`) byte-identical results.jsonl as v0.6. Existing single-agent CLI paths unchanged.
2. **`--git-cascade` adapter creates real worktrees.** A 2-task fanout with `branchPolicy: { kind: "stream" }` produces two worktrees under `.swarm-harness/worktrees/<id>/` and the workers' `process.cwd()` is the worktree path.
3. **Other branch-policy kinds remain no-ops at spawn.** `kind: "none"|"reuse"|"create"` produce no worktree; spawned workers inherit orchestrator cwd.
4. **Tracker survives orchestrator restart.** Two sequential `swarm run --git-cascade` invocations against the same repo see each other's streams in the tracker db (via `tracker.listStreams()`).
5. **MAP adapter forwards cascade events.** With `--map ws://...` + `--git-cascade`, `x-cascade/stream.opened` events appear on the MAP wire.
6. **Test posture.**

## Risks & mitigations

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| `process.cwd()` is not a git repo when adapter is constructed | Med | High | Constructor validates `git rev-parse --show-toplevel` at creation; surfaces a clear error before spawn. |
| Tracker db on networked filesystems (NFS) corrupts under concurrent sqlite writes | Low | High | `${repoPath}/.swarm-harness/` is project-local — usually local disk. Document NFS limitation in 7A.5 README update. |
| Worktree path > 104 chars on darwin (mirrors V0.5.Q5b daemon issue) | Low | Med | Path scheme is `${repoPath}/.swarm-harness/worktrees/<short-streamId>/` — streamIds are short ulids, not long names. Test on darwin in 7A.3. |
| Concurrent `kind: "stream"` spawns race for the same branch name | Low | Med | git-cascade serializes through its sqlite db; `createStream` is atomic. Mitigation already in the library. |
| `--git-cascade` + `--opentasks` + `--agent-inbox` constructor order | Med | Low | All three wrap StandaloneHost via composable options (taskWrapper / inboxBackend / branchPolicyAdapter). They don't conflict; each is independent. Test the all-three combo in 7A.3. |
| 1d estimate slips because git-cascade API has more surface than expected | Med | Med | Stages are independent — 7A.1 + 7A.2 are tiny; can ship as `v0.7-7A-rc` without 7A.3 if the adapter integration takes longer. |

## Stage 7B — released 2026-05-06

- New `commitChanges` method on `BranchPolicyAdapter` + `SwarmHost`; `GitCascadeBranchPolicyAdapter` routes through `tracker.commitChanges` so per-agent commits land with Change-Id trailers + audit log.
- New `task.commit_changes` IPC method (orchestrator-side handler resolves the calling agent's stream + worktree).
- New tier-2 `commit_changes` tool — workers call it instead of `bash git commit` to participate in the audit trail.
- Tests at close-out: 1849/1849 (was 1843, +6).

## Stage 7C — released 2026-05-06

- New `streamIdFor` + `mergeStream` adapter methods, mirrored as `streamIdFor` + `mergeStreamForAgent` on `StandaloneHost`.
- New `coordination.mergeStreams: { targetStream, strategy?, failOnConflict? }` field on `TeamSpec`. PeerTeamTopology auto-merges every member's stream into the configured target after a successful run.
- Conflicts emit a `team_note` lane event by default; opt into `failOnConflict: true` to surface as topology errors.
- Cascade rebase deferred — meaningful only once pipeline-of-streams parent linkage is in place.
- Tests at close-out: 1860/1860 (was 1849, +11).

## Stage 7D — released 2026-05-06

- New `StandaloneHost.supportsStreams()` discriminator + `applyDefaultBranchPolicy` topology helper. PeerTeamTopology now defaults each member to `{ kind: "stream" }` when the host has a stream-aware adapter and neither member nor coordination overrides set a policy.
- New `swarm-harness worktree list|clean` subcommand for managing `<repo>/.swarm-harness/worktrees/`. `clean` shells out to `git worktree remove --force` per worktree, then `git worktree prune`. `--dry-run` previews; `--json` machine-reads the list.
- Per-topology defaults beyond PeerTeam (Pipeline fork-from-prev, Coordinator/Committee/CriticLoop) and worktree-cleanup-on-exit remain follow-up scope.
- Tests at close-out: 1880/1880 (was 1860, +20).
