# `demo/` — "see and steer your swarm" recording

A reproducible, **zero-API-spend** screen recording of `openswarm team watch`
for the README hero + launch post. Rendered with
[VHS](https://github.com/charmbracelet/vhs) (Charm's scripted terminal
recorder), driven entirely by a curated `events.jsonl` — no live model run, no
daemon, fully deterministic.

![see and steer your swarm](see-and-steer.gif)

## Why this is cheap + deterministic

`openswarm team watch <name>` renders its multi-pane board (per-member `[role]`
lanes + a task board) as a **pure re-projection** of a team daemon's
`events.jsonl`:

```
events.jsonl → parseTeamEventsLog → lane-translator → RichRenderer → terminal
  (src/swarm/events-log.ts)  (src/acp/lane-translator.ts)  (src/acp/rich-view.ts, rich-format.ts)
```

It does **not** need a live model run to render — it just tails/re-projects the
file. So we hand-author the `events.jsonl` and dribble it into the path
`team watch` reads. Every record matches the real `LaneEvent` wire shape
(`src/swarm/events.ts`).

## Prerequisites

- **vhs** — `brew install vhs` (pulls `ttyd` + `ffmpeg`).
- **node** — to run the CLI + the event dribbler.
- The CLI must be runnable. `demo/demo-env.sh` prefers the existing node bundle
  `dist/cli.js`; if absent it falls back to `bun src/cli.ts`. (No build is
  required if `dist/` already exists.)

## Record it (one command)

```bash
vhs demo/see-and-steer.tape
```

Output lands at **`demo/see-and-steer.gif`** (~29s, ~750 KB, 1000×880).

To sanity-render the curated board offline (no VHS), through the *real* render
pipeline:

```bash
node demo/render-check.mjs
```

## How `team watch` is pointed at the curated log

There is **no flag** to point `team watch` at an arbitrary log, so we stage a
fake daemon directory at the path the CLI already resolves. `computeTeamPaths`
(`src/cli/team-paths.ts`) resolves:

```
$XDG_RUNTIME_DIR/openswarm/teams/<name>/events.jsonl
```

`demo-env.sh` sets `XDG_RUNTIME_DIR=/tmp/osw-demo`, so
`openswarm team watch review` reads
`/tmp/osw-demo/openswarm/teams/review/events.jsonl`. `play-events.mjs` writes
there. No daemon, no socket, no model.

## The storyboard

1. `openswarm team start review --detach` — starts the run (illustrative; see
   note below). Kicks off the **base** dribbler in the background.
2. `openswarm team watch review` — the board fills in live: architect, reviewer,
   and implementer spawn, `[role]`-attributed tool calls stream (incl. an edit),
   the task board flips ◐→●, and the lead lane narrates with running token/cost.
3. `openswarm team send review "also check error handling"` — a **mid-run
   steer**. Appends the steer reaction to the log.
4. `openswarm team watch review` — the swarm reacts: the reviewer audits error
   paths, the implementer wraps `verify()` in try/catch, and the board completes.

## Curated log structure + regeneration

`events/see-and-steer.events.jsonl` is generated by `gen-events.mjs`:

```bash
node demo/gen-events.mjs
```

- Line 1 is the `_metadata` header (`wire-protocol.ts`).
- Each subsequent line is a `LaneEvent`: `{ ts, agentId, type, payload, provenance? }`.
  For engine events (`text_delta` / `tool_use_*` / `tool_result`) `payload` **is**
  the raw `NormalizedEvent`, exactly as a worker forwards it.
- **No `tool_use_input` lines (#26).** A real daemon strips those deltas as
  live-only at write time (`wire-protocol.ts`). For edit/write tools the worker
  instead attaches a bounded, secret-redacted `input` object directly on the
  recorded `tool_use_end` (`worker-entry.ts` → `editInputForToolEnd`), and
  `team watch` reconstructs the inline diff from it (`normalized-translate.ts`
  consumes `ne.input` → `diffContent`). The fixture mirrors this exactly, so it
  can't hide a regression in that reconstruction path. Non-edit tools carry no
  `input`, so their board titles are generic (`Read file` / `Search`).
- `agentId` matches a `worker_spawned` `childAgentId` so the translator resolves
  each event's `[role]` + lane.
- Post-steer records are tagged `provenance: "steer"`; the player replays the
  base arc first, then the steer-tagged records on `team send`.
- Real `team_usage` (#17) roll-ups drive the per-member + `Σ team` usage ledger.

### Fallback: harvest a real log

Driving from the canned log is the preferred path. If you ever need a real one,
capture one short cheap run and reuse its `events.jsonl`:

```bash
# cheapest model, trivial task, tight budget → then copy the daemon's log
openswarm team start review --detach   # (real, once presets land)
cp "$XDG_RUNTIME_DIR/openswarm/teams/review/events.jsonl" demo/events/
```

## Notes, honesty, and src follow-ups

- **`team start` / `team send` are log-driven shims** in `demo-env.sh` for the
  recording. The real `team start` would spin up a daemon + real agents (API
  spend, nondeterministic); the real `team send` needs a running daemon socket.
  Both are shown as authentic-looking commands while the render stays log-driven.
  `team watch` is the **real** CLI command.
- **Once built-in team presets land**, `openswarm team start review` becomes a
  real zero-YAML invocation; today it is illustrative and the render is
  log-driven.
- **Renderer status:**
  - The terminal board formatter (`rich-format.ts`) now surfaces the inline
    **diff** carried on edit tool-calls (#26) and **per-member token/cost** plus
    a `Σ team` total from `team_usage` (#17) events (#25). The demo exercises both
    directly from the curated log — validate offline with `render-check.mjs`.
  - A `--events-log <path>` (or `--from <dir>`) flag on `team watch` would let a
    demo/replay point at an arbitrary log **without** the `XDG_RUNTIME_DIR`
    staging trick used here (still a candidate follow-up).

## Live token spend

**Zero.** `team watch` only reads a file; the dribbler only writes one. No model
requests are made.
